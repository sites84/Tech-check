Como colocar a NPU da Intel para funcionar no Ubuntu usando o OpenVINO e o llama.cpp

Veja o passo a passo detalhado para configurar e rodar a NPU de processadores Intel em um sistema Ubuntu 26.04, superando barreiras de binários pré-compilados e utilizando ferramentas dedicadas para IA.

A utilização de unidades de processamento neural vem avançando rapidamente no ecossistema Linux. Enquanto o suporte a NPU da AMD no Ubuntu apresentou melhorias significativas com a simplificação de pacotes em versões recentes do sistema operacional, explorar o hardware da Intel exige o auxílio do ecossistema OpenVINO. Para quem deseja testar o backend OpenVINO do llama.cpp, o processo envolve etapas manuais de compilação e configuração de drivers.

Preparação do ambiente e falhas em binários prontos

Nos testes práticos realizados com um mini PC GMKtec NucBox K17, equipado com o processador Core Ultra 5 226V e 16 GB de memória RAM, a versão do sistema utilizada foi o Ubuntu 26.04.1. O modelo superior NucBox K17 PLUS também é apontado como uma alternativa interessante devido à menor diferença de preço e ao dobro de memória.

Ao tentar utilizar o binário pré-compilado disponível na página de lançamentos do llama.cpp, especificamente a versão identificada como Ubuntu x64 (OpenVINO), o comando de benchmark falhou imediatamente com um erro de instrução ilegal ao carregar o modelo Qwen3-8B-Q4_K_M.guff. Por conta disso, a compilação manual a partir do código-fonte tornou-se o caminho necessário para prosseguir com os testes na máquina.

Instalação do OpenVINO e dos drivers da NPU

A instalação do OpenVINO Runtime no Linux foi realizada a partir de um arquivo compactado, método obrigatório para viabilizar a compilação posterior com o llama.cpp. Os comandos executados para obter e estruturar a versão 2026.4.0 foram os seguintes:

  • Criação do diretório de destino em /opt/intel e download do pacote compactado oficial
  • Extração e movimentação dos arquivos para a pasta /opt/intel/openvino_2026.4.0
  • Execução do script de dependências de instalação do OpenVINO
  • Configuração prévia do ambiente executando o script setupvars.sh antes de utilizar as ferramentas

Já a instalação do driver da NPU da Intel utilizou pacotes diretos em vez do formato snap, evitando o atraso na chegada de atualizações recentes. A versão utilizada foi a 1.38, exigindo a execução de passos adicionais:

  • Download do pacote do driver Linux NPU na página oficial do GitHub
  • Instalação das bibliotecas dependentes, incluindo libtbb12 e pacotes de carregadores gráficos locais
  • Adição do usuário atual ao grupo render para concessão de permissões de hardware
  • Reinicialização completa do sistema para aplicar as alterações de grupo e drivers

Compilação do llama.cpp e seleção de modelos

Com o OpenVINO e o driver devidamente configurados, o próximo passo consistiu em clonar e compilar o repositório oficial do llama.cpp com suporte ao backend OpenVINO ativado. O processo de compilação utilizou as ferramentas build-essential, CMake e Ninja, ativando a flag de compilação -DGGML_OPENVINO=ON.

Na escolha dos modelos compatíveis, a documentação oficial exibe tabelas de validação onde o símbolo correspondente indicava restrições inesperadas para o uso ideal com a NPU, levando à escolha do modelo Qwen3-8B-Q4_K_M para os testes iniciais de execução via linha de comando com a variável de ambiente direcionada para a NPU.

Aplicação alternativa com a ferramenta onw

Para contornar limitações visuais e operacionais da interface de linha de comando pura, desenvolveu-se uma aplicação específica chamada onw para interagir diretamente com o OpenVINO. O aplicativo pode ser instalado de forma automatizada por meio de um script via terminal e oferece uma interface web para gerenciar servidores e modelos de inteligência artificial.

O uso do onw permite carregar modelos variados e realizar testes práticos, como a análise de imagens enviadas a modelos de visão computacional, embora existam limitações operacionais relativas à resolução máxima de 512 pixels com redimensionamento forçado para proporção quadrada em certas configurações. Além disso, a aplicação consegue executar modelos maiores, como o Qwen3.6-35B-A3B, através de mecanismos que descarregam parte dos dados para o armazenamento SSD, viabilizando o funcionamento em hardwares com restrição de memória RAM.

Por que isso importa

A matéria demonstra na prática como desenvolvedores e entusiastas podem superar barreiras técnicas e de compatibilidade para aproveitar aceleradores de inteligência artificial integrados (NPUs) em hardwares de consumo rodando sistemas operacionais abertos como o Ubuntu.

O que pode acontecer no futuro

Se essa tendência continuar, o suporte nativo a NPUs em distribuições Linux pode se tornar cada vez mais automatizado e integrado a ferramentas de ponta, reduzindo a necessidade de compilações manuais e facilitando o uso local de modelos avançados de IA.
